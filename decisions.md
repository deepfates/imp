# Decisions

One line per ruling. Each names its source, its status, and the condition under
which it stops applying. A reason marked *unverified* is stated in the source
but has no retained failure or measurement behind it; treat it as a claim, not
a fact. Dates are when the ruling entered this repository (from `git log`),
not necessarily when it was made.

| 2026-09-25 | Prompts and parsed values use neutral spellings: types in words (`string`, `integer`, `true or false`, `one of: a, b`, `list of strings`, `object`, declared once in `Imp.Adapter.FieldType`), values in JSON (`null`, `true`, `["x", "y"]`), in every adapter, ReAct, and the MIPROv2, GEPA and SIMBA prompts. A non-string answer for a string field is kept as its JSON text; a null is no value. Parity with DSPy means the same fields, order and constraints in the prompt, the same fields and types accepted, and the same errors raised, not DSPy's text or Python's `str()` spelling. | The owner's intention, 2026-09-25: Python spellings (`Literal[...]`, `True`, `None`, `repr(Example)`) read as foreign in an Elixir library and teach the model nothing the neutral words do not. `test/adapter_type_wording_test.exs`, `test/upstream_exam/adapters_test.exs`; the golden trace and the MIPROv2 proposer differentials compare prompts after putting DSPy's spellings into Imp's words (`Imp.DSPyWording`). | In force. | Does not retire. |
| 2026-09-25 | A tool call's value alone never reads as `:refused`: `Imp.Tool.outcome/1` says `:refused` only for an `Imp.MCP.CallFailure` or an MCP error result that declares it in `structuredContent.outcome` (`"refused"`, `"auth_refused"`, `"unknown"`), and ReActV2 and RLM decide their own refusals where they refuse the call and record them as `metadata.outcome`. | `lib/imp/tool.ex` `outcome/1`, `test/mcp_call_outcome_test.exs`. A tool can return any term, including one shaped like Imp's refusals, and `:refused` tells a caller that repeating the call is safe; reading it from a term a tool that ran can produce would retry a write that landed. The declared outcome is how a server that knows more (Kite, for a write that may have been applied) says so. | In force. | Does not retire. |

| 2026-09-25 | A failed LM request from `Imp.Clients.ReqLLM` is one `%Imp.LMError{}` with `status`, `retryable` and `context_window_exceeded`, and ReqLLM's own error under `reason`; `Imp.ContextWindowExceededError` is gone into it. | 2026-09-25 | A completion that cannot be read as a signature's outputs is `%Imp.AdapterParseError{}` with a `:kind` (`:malformed`, `:missing_fields`, `:invalid_fields`, `:unsupported_output`, `:other`), from every built-in adapter and from `Imp.Predict`, which fills `:trace` and, for `n > 1`, `:completion_index`. | 2026-09-25 | An error reason is a term: a raise keeps the exception struct and a throw or exit is `{kind, value}`, for every `*_failed` / `*_error` tag Imp builds at a public boundary (`:lm_failed`, `:module_call_failed`, `:retriever_failed`, `:tool_error`, `:tool_policy_error`, MCP and ACP callbacks). One tag has one shape. `Imp.Redaction` keeps an exception's type while redacting its fields. | `test/error_shapes_test.exs`. A reason that is only text can be acted on only by matching it, and one tag with two shapes breaks every exhaustive match. | In force. | Does not retire. |
| 2026-09-25 | `Imp.Example` and `Imp.Prediction` keep each key as the atom or string it was given, and every key lookup compares by text. | `lib/imp/field_map.ex`, `test/field_key_type_test.exs`. | 2026-09-24 | A run event sink that raises, throws or exits is reported to the run's owner as `{:imp_run_event_sink_failed, run_id, %{sequence, kind, reason}}`. Imp marks no gap itself, because a sink that failed may still have stored the event; the host decides what its record says. Stopping or cancelling a run reports every event the sink had not finished with, the one in the sink as `:in_sink_when_stopped` and the rest as `:never_handed_to_sink`. | `lib/imp/run.ex` moduledoc and `Imp.Run.EventDelivery`, `test/run_event_sink_failure_test.exs`; workshop `docs/constellation-work.md` W3.2. A host that stores events as the run's record lost events silently when its store call timed out, and the record read as complete. | In force. | Does not retire. |
| 2026-09-24 | How many runs a host may have at once is the host's setting: `Imp.Run.start/3` with `admission: {pool, limit}` counts the run in the host's named pool, not the machine-wide `:async_max_workers` pool, and a full pool returns `{:error, :busy}` at once rather than waiting. Without it a run waits for the machine-wide pool as before. | `lib/imp/run.ex` `start/3`, `Imp.Tasks.Admission`, `test/run_admission_test.exs`; workshop `docs/constellation-work.md` W3.3. A wait inside `start/3` blocks the caller's mailbox and hides the queue where the host cannot order it; a host that owns its runs knows when one ends and can start the next. | In force. | Does not retire. |
| 2026-09-24 | An MCP tool call that got no answer from its tool returns `%Imp.MCP.CallFailure{}` with an `outcome` of `:refused`, `:not_sent` or `:unknown`, decided in Imp where ExMCP's error arrives, with ExMCP's error kept unchanged in `reason`. | 2026-09-24 | Under `on_failure: :drop`, an `"sse"` descriptor refused for carrying `"headers"` or `"auth"` (`:mcp_sse_credentials_refused`), or for a URL with a query string (`:mcp_sse_url_refused`), is left out with a warning, as an unreachable server is, rather than refusing the import; under the default `:refuse` it still refuses the import. | Owner ruling, 2026-09-24. `lib/imp/mcp/connections.ex` `connect_all/5`, `test/mcp_legacy_sse_test.exs` "under on_failure: :drop leave out only that server". | 2026-09-16 | `Imp.MCP.connect/2` drops a server it cannot connect only when the caller asks for it (`on_failure: :drop`), and even then only for a failed dial and a failed `tools/list`: an unauthorized descriptor, a declared `auth` that cannot produce a header, a malformed descriptor and anything the caller's `:tool_filter` raises still refuse the whole import. | 2026-09-16 | Each MCP dial is bounded by `:timeout` on its own, and a dial abandoned at that deadline is killed together with the half-open client it is linked to. | `lib/imp/mcp/connections.ex` `dial/2` and `abandon/1`, `test/mcp_connection_test.exs`.
