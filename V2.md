# Production Ready V2

V2 expands the original DSPy-shaped Elixir port toward the adjacent Ax and
optimize-anything ecosystem: arbitrary artifact optimization, Pareto/ASI GEPA,
agent runtime affordances, MCP-style tool discovery, schema constraints, and
deterministic benchmark fixtures.

## Gates

V2 is complete only when all of these pass:

```sh
mix v2.check
mix production.check
LIVE_PROVIDER=1 mix test --include live test/live_provider_test.exs
```

`mix v2.check` enforces [V2_ROADMAP.md](V2_ROADMAP.md), warnings-as-errors
compilation, formatting, and V2 benchmark tests.

## Optimize Anything

```elixir
artifact = DSPy.Optimize.Anything.new_artifact(:config, "mode=slow")

report =
  DSPy.Optimize.Anything.optimize(
    artifact,
    fn artifact, _examples ->
      if artifact.text =~ "mode=fast", do: 1.0, else: 0.0
    end,
    trials: 1,
    mutation_fn: fn _artifact, _trial, _seed -> "mode=fast" end
  )

report.best.score
#=> 1.0
```

Reports preserve baseline candidates, lineage, diagnostics, evaluator errors,
named artifact parameters, and JSON-safe save/load via
`save_report!/2` and `load_report!/1`.

## Pareto/ASI GEPA

```elixir
artifact = DSPy.Optimize.Anything.new_artifact(:prompt, "Base")

report =
  DSPy.Optimize.GEPA.optimize(
    artifact,
    fn artifact, examples ->
      %{
        per_example_scores:
          Enum.map(examples, &if(String.contains?(artifact.text, &1), do: 1.0, else: 0.0)),
        asi: Enum.reject(examples, &String.contains?(artifact.text, &1))
      }
    end,
    examples: ["Paris", "concise"],
    generations: 2,
    mutation_fn: fn _artifact, asi, _generation -> Enum.join(asi, "\n") end
  )

report.best.aggregate_score
#=> 1.0
```

GEPA tracks per-example scores, Pareto frontier membership, ASI diagnostics,
candidate lineage, replacement branches, and system-aware merges.

## Agents And MCP

```elixir
tool = DSPy.Tool.new(:double, "double a number", fn %{x: x} -> %{y: x * 2} end)

agent =
  DSPy.Agent.new(:doubler, fn %{x: x}, runtime ->
    DSPy.Agent.call_tool(Process.get(:agent), :double, %{x: x}, runtime)
  end, tools: [tool])

Process.put(:agent, agent)
{:ok, %{y: 8}, runtime} = DSPy.Agent.run(agent, %{x: 4})
runtime.traces
Process.delete(:agent)
```

MCP-style catalogs import external schemas into ordinary `DSPy.Tool` structs:

```elixir
catalog =
  DSPy.MCP.Catalog.new([
    %{name: :lookup, description: "lookup", input_schema: %{required: [:key]}, run: & &1}
  ])

[tool] = DSPy.MCP.import_tools(catalog)
```

Runtime sessions support memory, large context references, tool failures, child
agents, streaming events, and trace capture.

## Schema Constraints

```elixir
signature =
  DSPy.Signature.new(%{
    inputs: [:question],
    outputs: [
      %{name: :answer, type: :string, constraints: %{enum: ["yes", "no"]}},
      %{name: :confidence, type: :number, constraints: %{min: 0.0, max: 1.0}}
    ]
  })

DSPy.Signature.json_schema(signature)
```

Supported constraints include enum, numeric bounds, string length, regex
patterns, arrays, nested objects, and optional fields. JSON adapter parse errors
return retry feedback suitable for another model attempt.

## Benchmarks

```elixir
DSPy.V2.Benchmarks.assert_pass!()
```

The required deterministic benchmark fixture covers:

- Ax-style structured extraction with schema constraints.
- Agent/tool execution with trace evidence.
- GEPA prompt optimization.
- Arbitrary config optimization.

## Migration From V1

V1 APIs remain intact. V2 adds new modules under `DSPy.Optimize.*`,
`DSPy.Agent`, `DSPy.MCP`, `DSPy.Schema`, and `DSPy.V2.Benchmarks`. Existing
programs, adapters, teleprompters, and provider contracts continue to pass the
same production gate.

## Honest Non-Goals

- This is not a byte-for-byte Python DSPy clone.
- The MCP support is a catalog/import contract and in-process fake transport;
  a networked MCP client should be added when targeting a real server.
- V2 benchmark fixtures are deterministic production gates, not broad public
  leaderboard claims.
- Provider-native schema APIs and live streaming are intentionally left as
  provider-specific follow-up work.
